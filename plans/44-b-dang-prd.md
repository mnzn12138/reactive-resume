**原始需求复述**:国内 PC 用户最习惯的登录方式(微信扫码、支付宝扫码)与移动互联网标配(手机号 + 短信验证码)在现有系统中全部缺失,登录入口只有邮箱/用户名密码与 Google/GitHub/LinkedIn;短信与对象存储则只能接国外服务商。B 档要把这三类登录入口与国产短信、国产对象存储补齐。

## 1. 产品目标

1. **让国内用户能用自己习惯的方式登录**:在登录页提供微信扫码、支付宝扫码、手机号 + 短信验证码三条入口,与现有邮箱/密码并存,由部署者按实例自主开关。
2. **让自托管部署者可配、可查、可关**:一切服务商凭证走环境变量,管理后台能一眼看到"配了什么、缺什么、能不能用",且能一键关闭某条通道而不影响其他通道。
3. **让国产化落到基础设施**:短信走阿里云/腾讯云持牌通道,对象存储可指向阿里云 OSS / 腾讯云 COS / 华为云 OBS,替代对国外服务商的依赖。

非目标:实名认证、商业化计费、OCR 导入(见 §2.3 C 档)。

**硬约束(写需求时已内化,不另行讨论)**

- 自托管产品,**凭证只能来自环境变量**(或由此派生的实例设置),不硬编码、不强制所有实例启用;`OVERRIDABLE_SETTING_KEYS`(`packages/auth/src/instance-settings.ts:21`)的解析顺序是 **DB 行 > 环境变量 > 内置默认**,B 档新开关必须沿用同一顺序。
- 面向用户的所有文案是中文,全部走 Lingui(`apps/web/locales/zh-CN.po` + `zh-TW.po`),不留硬编码中文字符串。
- 不采集、不存储任何与登录无关的个人信息。

## 2. 用户故事

### B1 微信扫码登录

1. As a **求职者**,I want 在登录页点"微信登录"后用手机微信扫一扫完成登录,so that 我不必记住邮箱密码,也不用翻墙可用的 Google/GitHub 账号。
2. As a **求职者**,I want 第一次用微信登录时看到并勾选《隐私政策》《用户协议》再建号,so that 我知道自己的哪些信息被收集、并确实是本人同意的。
3. As a **求职者(已有邮箱账号)**,I want 在设置页把微信绑到现有账号,so that 我以后可以扫码直接进,简历数据不会分成两个账号。
4. As a **自托管部署者(管理员)**,I want 在环境变量里填好 `WECHAT_APP_ID` / `WECHAT_APP_SECRET` 后登录页自动出现微信按钮,so that 我不需要改代码也不需要所有实例都启用。
5. As a **自托管部署者(管理员)**,I want 在管理后台看到"微信:已配置 / 未配置(缺哪个变量)"并能一键关闭微信登录,so that 凭证填错或到期时我能快速定位并止损。

### B2 手机号 + 短信验证码

1. As a **求职者**,I want 用"邮箱 / 手机号"Tab 切到手机号登录,输入手机号收 6 位短信码即可登录(无账号则自动注册),so that 我没有常用邮箱也能用。
2. As a **求职者**,I want 看到"获取验证码"按钮的 60 秒倒计时与"已发送至 138\*\*\*\*8000"提示,so that 我知道短信发出去了、什么时候能重发,不会连点刷爆。
3. As a **求职者(已有邮箱账号)**,I want 在设置页绑定/更换手机号并看到脱敏显示,so that 我的账号多一种找回方式,且手机号不会被明文展示。
4. As a **自托管部署者(管理员)**,I want 在环境变量里选短信服务商(阿里云 / 腾讯云)并配好 AccessKey、签名、模板 ID,so that 短信走国内持牌通道,到达率可控。
5. As a **自托管部署者(管理员)**,I want 点"发送测试短信"时看到厂商返回的真实错误码(如 `InvalidAccessKeyId`、`isv.SMS_TEMPLATE_ILLEGAL`),so that 我能自助排错,而不是只看到一个"失败"。

### B3 支付宝扫码登录

1. As a **求职者**,I want 在登录页用支付宝扫码登录,so that 我在没有微信或不愿用微信时仍有国产扫码入口。
2. As a **求职者**,I want 支付宝授权后即使拿不到昵称头像也能登录、之后自己在设置页补,so that 能力未签约不会把我挡在门外。
3. As a **自托管部署者(管理员)**,I want 支付宝与微信的开关、诊断、绑定/解绑体验完全一致,so that 我只需要学一次配置方法。

### B4 国产对象存储

1. As a **自托管部署者(管理员)**,I want 在环境变量里把存储指向阿里云 OSS / 腾讯云 COS / 华为云 OBS,so that 国内服务器读写图片不必绕国外 S3。
2. As a **自托管部署者(管理员)**,I want 启动时若 endpoint / region / path-style 组合明显错误能得到一条明确提示,so that 我不会在"上传成功但打不开"上耗半天。
3. As a **求职者**,I want 换存储后我的头像、简历图片照常显示,so that 后端换服务商对我无感。

## 5. 关键流程

### 5.1 微信扫码登录时序(跳转式,P0)

```
用户            前端                服务端(genericOAuth)         微信开放平台
 │  勾选同意 +     │                        │                          │
 │  点"微信登录"   │                        │                          │
 │──────────────>│  signIn.social(wechat)  │                          │
 │               │───────────────────────>│                          │
 │               │                        │ G1 校验 legalConsent      │
 │               │                        │ (不过 → FORBIDDEN,跳不出)│
 │               │                        │ G2 addOAuthServerContext  │
 │               │                        │  + requestSignUp=true     │
 │               │                        │ 生成 state(含 callbackURL │
 │               │                        │ 与模式:登录/绑定)         │
 │               │        302             │                          │
 │<──────────────│<───────────────────────│                          │
 │─────────────────────────────────────── 浏览器跳转 ───────────────>│
 │                                                    qrconnect 扫码页 │
 │  手机微信扫一扫并确认 ──────────────────────────────────────────>│
 │                                                                    │
 │                                        302 code + state ───────────│
 │                                        GET /api/auth/callback/wechat│
 │                                        │                          │
 │                                        │① 校验 state              │
 │                                        │② code → access_token      │
 │                                        │   (appid+secret, 得        │
 │                                        │    openid / unionid)      │
 │                                        │③ sns/userinfo → nickname  │
 │                                        │   / headimgurl            │
 │                                        │④ 按 unionid ?? openid     │
 │                                        │   查 account 表           │
 │                                        │⑤ 分支见 §5.3 矩阵         │
 │                                        │⑥ G4:同请求内建号 +        │
 │                                        │   写 user_consent         │
 │<───────────────────────────────────────│                          │
 │  302 到 /dashboard(无同意中间页)         │                          │
```

要点:

- `redirect_uri` = `${APP_URL}/api/auth/callback/wechat`,**必须与开放平台后台登记的回调域名一致**;微信不接受 `localhost` 之外的非法域名,本地联调要靠内网穿透或 hosts。
- 微信**不支持 PKCE**,`state` 是唯一 CSRF 防护,必须校验且不可预测;而 better-auth 的 `pkce` **默认 `true`**,因此必须显式 `pkce: false`,否则授权请求会带上 `code_challenge` 被微信拒绝(静默失败)。
- `#wechat_redirect` 必须直接写进 `authorizationUrl`(它是 fragment,走 `authorizationUrlParams` 会被塞进 query);`scopes: ["snsapi_login"]` 必须走顶层配置(`scope` 属保留参数,写在 `authorizationUrlParams` 里会被静默丢弃)。
- `unionid` 仅在应用已绑定到开放平台账号时返回;未绑定时回落 `openid`(跨应用不通)。
- 框架会强制写入 `client_id`,微信预期的是 `appid`(多一个参数)。按"多余参数被忽略"处理,但**必须在单测里固定该假设**,并在报告中标注为"未真实调用验证"。

### 5.2 支付宝扫码登录时序

与 §5.1 同构,差异三点:

1. 授权 URL 走 `openauth.alipay.com/oauth2/publicAppAuthorize.htm`,`scope=auth_user`。
2. **换取 token 不是标准 OAuth2 端点**:走 `openapi.alipay.com/gateway.do`,`method=alipay.system.oauth.token`,请求需 **RSA2 签名**(A-3),响应需**验签**(A-4)。
3. 昵称头像取 `alipay.user.info.share`(需签约"获取会员信息"),**未签约时不报错、字段留空**(A-2),用户可在设置页自行补全。

> **已关闭(45 号 §1.1 核实结论):不建适配路由。** `genericOAuth` 原生提供 `getToken` / `getUserInfo` 两个完全接管点(类型注释原话:"useful for providers with non-standard token endpoints"),且有 `getToken` 时 `tokenUrl` 可省。支付宝的 RSA2 签名与响应验签、微信的 GET-query 换取**直接写在这两个函数内部**,仍是真实驱动,不降级为 mock。PRD 原预留的 0.5~1 天**省回**。

### 5.3 账号关联口径(最关键,逐条明确)

**匹配键**

| 通道 | 匹配键 | 存储位置 |
|---|---|---|
| 微信 | `unionid ?? openid` | `account.accountId`(经 `accountSubject` 解析) |
| 支付宝 | `user_id`(buyer_id) | `account.accountId`(经 `accountSubject` 解析) |
| 手机号 | E.164 `+8613800138000` | `user.phoneNumber`(由 better-auth `phoneNumber` 插件建列) |

> **本期不另存 `openid`**:`account` 表没有现成的 metadata 列,留一份就要再加一列 + 一条迁移(即第 11 处登记点)。若日后绑定了开放平台需要回填,再单独立项。

**场景矩阵(三种通道通用)**

| # | 登录态 | 匹配结果 | 处理 | 落 `user_consent` |
|---|---|---|---|---|
| 1 | 未登录 | 命中已有 `account` | 直接登录,发会话 | 否(注册时已同意) |
| 2 | 未登录 | 未命中 + 允许注册 | **前置同意**:跳转前未勾选 → G1 直接 FORBIDDEN(跳不出去,不建号);已勾选 → 回调**同请求内**建号 + 落 `user_consent` → 放行 | 是(§5.5) |
| 3 | 未登录 | 未命中 + 禁止注册 | 拒绝,`/auth/error` 提示"未开放注册" | 否 |
| 4 | 已登录 | 未命中 | 绑定到当前账号(`account` 增一行) | 否 |
| 5 | 已登录 | 该键已绑到**另一个**账号 | 拒绝,提示"该账号已绑定其他账号,请先解绑" | 否 |
| 6 | 已登录 | 该键已绑到**当前**账号 | 无操作,提示"已绑定" | 否 |

**微信/支付宝不返回邮箱** → 建号时必须生成:

- `email`:占位地址 `wechat_<accountId>@users.noreply.<实例域>`(支付宝同理),`emailVerified = false`,**不发送验证邮件**(发送必然失败)。`<实例域>` **从 `APP_URL` 派生**;`APP_URL` 缺失或不可解析时**回落 `users.noreply.local`**。
- `username` **与 `displayUsername`**:两者在 `packages/db/src/schema/auth.ts` 里**都是 `notNull().unique()`**,必须同时生成,漏一个就 NOT NULL 报错。取值走 `toUsername()` 归一化(`config.ts:476-483` 的 `^[a-z0-9._-]+$`,长度 3~64);`user.additionalFields.username` 是 `required: true`。
- `name`:厂商昵称,缺失时用通道名 + 后 4 位(如"微信用户 a1b2")。
- 设置页提供**补填邮箱**入口;补填后走现有 `changeEmail` 邮件验证流程,`emailVerified` 置真。
- **绑定已存在账号时依赖 G-7**:微信/支付宝是占位邮箱,`accountLinking` 不开 `allowDifferentEmails: true` 会直接 `EMAIL_DOES_NOT_MATCH`,表现为"点了绑定没反应/跳错误页"的静默失败。

**手机号特殊分支**(发码后才知道有没有号):

| 情况 | 处理 |
|---|---|
| 校验通过 + `user.phoneNumber` 已存在 | 直接登录该账号(**不会**因重复注册产生第二账号) |
| 校验通过 + 不存在 + 已登录(设置页绑定) | 写入当前账号,`phoneNumberVerified = true` |
| 校验通过 + 不存在 + 未登录 + 允许注册 | 前置同意已勾选 → 建号(占位邮箱 `<11位>@<实例域>` + 生成 `username` / `displayUsername`)+ **同请求内**落 `user_consent`(来源 `signup-phone`);未勾选 → FORBIDDEN |
| 校验通过 + 不存在 + 未登录 + 禁止注册 | 拒绝,提示"该手机号未注册,且本实例未开放注册" |

**解绑**:解绑前校验"剩余登录方式数 ≥ 1",否则禁用并说明。解绑手机号后 `phoneNumber` 置空、`phoneNumberVerified` 置假。

### 5.4 验证码发送 / 校验 / 重发 / 防刷

| 环节 | 规则(建议默认值) |
|---|---|
| 发送前置 | 手机号格式校验通过;未被限流;实例未关闭短信登录 |
| 冷却 | 同一手机号 **60 秒**;倒计时结束才可"重新发送" |
| 频次 | 同一手机号 **10 次/天**;同一 IP **20 次/小时**(超限返回中文提示,不发短信) |
| 码长 / 有效期 | 6 位数字 / **300 秒**(`expiresIn = 300`) |
| 校验次数 | 最多 **3 次**(`allowedAttempts = 3`);失败 3 次或超时即作废,需重发 |
| 存储 | 验证码由 better-auth OTP 机制保管;**不写日志、不回显、不进埋点** |
| 审计 | 只记脱敏手机号 + 厂商 + 结果码 + 时间(保留 30 天),不记验证码 |
| 重发 | 重发使旧码立即失效(同一手机号只保留最新一码) |
| 失败文案 | 统一为"验证码错误或已过期,还可尝试 N 次",**不区分**"码错"与"过期"(防枚举) |

### 5.5 同意记录(`user_consent`)口径 —— **B″ 前置同意**(已按 `45-b-dang-design.md` §1.3 重写)

现状:`consentSourceFor`(`packages/auth/src/config.ts:72`)只认 `/sign-up/email`,理由是"第三方跳转里用户根本没看到勾选框,写一行等于伪造同意"。B 档新增两条注册通道后,这个洞会从 1 条扩到 3 条。

**产品口径:要补,且必须补在"账号被创建之前,用户已经明确表达同意"的位置。**

**为什么不是"回调后中间页"**:better-auth 1.7.3 的 `databaseHooks.user.create.before` 只收到 `newUser`、无请求上下文、抛错也不产生重定向;OAuth 回调跑完时账号与会话**已经落库**,框架没有"暂停并稍后恢复"的状态机(45 号 §1.1 F1 / F8 / F10)。原设想的"取消同意再删号"是唯一补救手段,但在"已建号"到"用户勾选"之间存在一个**账号已存在且无 `user_consent` 记录**的窗口 —— 这正是 A10 时刻意消灭的状态(当时把 `/callback/:id` 排除在 `consentSourceFor` 之外,理由就是"不能伪造一条没发生的同意")。该窗口**不可接受**。

**B″ 方案:勾选前置到登录页(§4.6),服务端四道闸门**

| 闸门 | 位置 | 作用 |
|---|---|---|
| **G1 版本校验** | `hooks.before` 匹配 `/sign-in/social` | 读 `ctx.body.legalConsent`,`legalConsentSchema.safeParse` + `version === legalDocumentVersion`;不合法直接 `APIError("FORBIDDEN")` —— **用户根本跳不出去**,自然也不会建号 |
| **G2 票据固化** | 同一个 before 钩子 | 校验通过后 `addOAuthServerContext({ legalConsent: { version, channel } })`(官方 API,加密写进 state,注释原话 "cannot be spoofed by the client",TTL 10 分钟);并**由服务端置位** `ctx.body.requestSignUp = true`,不接受客户端传入值 |
| **G3 建号阻断** | provider 配置 `disableImplicitSignUp: true` | 即使 G1/G2 被绕过,回调里 `disableImplicitSignUp && !requestSignUp === true` → 走"signup disabled"分支,**不会建号**;已存在的账号仍正常登录(只阻断创建分支) |
| **G4 落库** | `hooks.after` 匹配 `/callback/wechat` `/callback/alipay` | `(await getOAuthState())?.serverContext?.legalConsent` 存在 **且** `newSession` 存在 → 复用现有 `recordConsent()` 写 `user_consent`,`source` = `signup-wechat` / `signup-alipay` |

**手机号通道(比 OAuth 更强,不需要任何中间页)**:手机号在**请求体里**,服务端在 `hooks.before` 就能判断该号是不是新用户 —— 命中 = 登录,直接放行;未命中 = 将注册,要求 `ctx.body.legalConsent` 通过校验否则 `FORBIDDEN`;`hooks.after` 同请求内写 `user_consent`,`source = signup-phone`(45 号 §1.4)。

**由此确定的三条口径**

1. `ConsentSource` 扩三个成员:`signup-wechat` / `signup-alipay` / `signup-phone`(文件位置 `packages/auth/src/config.ts:54`);`"manual"` 继续保留为未启用的预留值。这是**记录模型**,与"是否有一个页面"无关 —— 原"三条通道共用 `/auth/consent` 页"的说法**随页面一并取消**。
2. **不存在"取消同意 = 删号"这条路径** —— 未勾选的用户在 `/sign-in/social` 阶段就被 G1 拦下,压根不会建号。也不再有"先建号后同意"的时间窗。
3. **代价(已接受)**:中间页拿不到第三方标识(回调后才知道),§4.4 中"已绑定(wxid_****a1b2)"的标识展示**降级为 P2**。
4. 同意文案与 `legalDocumentVersion` 绑定;版本 bump 后老用户的"重新同意"仍走已预留的 `"manual"` 来源(**本期不做**,沿用 A10 取舍)。
