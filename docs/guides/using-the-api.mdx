---
title: "Using the API"
description: "Authenticate REST requests with an OAuth2 access token and integrate resume data into your own scripts, apps, or automations."
---

The Reactive Resume API is the same API the dashboard and the MCP server use. Every instance publishes its own OpenAPI 3.1 specification, so the reference always matches the deployment you are talking to.

<Info>
  The API is served under `/api/openapi`. If you're self-hosting, replace `https://rxresu.me` with your instance URL.
</Info>

<Steps>
  <Step title="Sign in to the dashboard">
    Head over to [https://rxresu.me](https://rxresu.me) and sign in with your account credentials.
  </Step>

  <Step title="Review the API reference">
    Open the [API Reference](https://docs.rxresu.me/api-reference) to see every route, its parameters, and its response schema.

    <Tip>
      Self-hosted instances serve their own spec at `/api/openapi/spec.json`. Point your tooling at that URL to generate a client for your deployment.
    </Tip>

  </Step>

  <Step title="Obtain an access token">
    Requests are authenticated with an OAuth2 access token sent as `Authorization: Bearer <token>`. Tokens are issued by the same OAuth2 authorization server that MCP clients use, so any OAuth2 client that supports dynamic client registration (RFC 7591) and PKCE can get one.

    - Authorization server metadata: `/.well-known/oauth-authorization-server`
    - Protected resource metadata: `/.well-known/oauth-protected-resource`
    - Login and consent: `/api/auth/oauth`

  </Step>

  <Step title="Authenticate requests with the token">
    Include the token in the <Badge>Authorization</Badge> header:

    ```bash
    curl "https://rxresu.me/api/openapi/resumes" \
      -H "Authorization: Bearer YOUR_ACCESS_TOKEN"
    ```

  </Step>

  <Step title="Handle expired tokens">
    Access tokens expire, and a user can revoke a client at any time. When a request comes back with `401`, run the OAuth2 flow again to get a fresh token and retry.

  </Step>
</Steps>

<Note>
  Managing connections through an AI client instead of writing code? See [Using the MCP server](/guides/using-the-mcp-server) — your client performs the same OAuth2 flow for you.
</Note>
