## Overview

Reactive Resume runs as a Node.js process on the host. Docker is only used to provide the infrastructure services:

<CardGroup cols={3}>
  <Card title="PostgreSQL">Stores accounts, resumes, and application data.</Card>
  <Card title="Redis">Stream and state for the AI agent workspace.</Card>
  <Card title="SeaweedFS">S3-compatible storage for uploads. Skip it and files are written to local disk instead.</Card>
</CardGroup>

The Compose files in this repository define those services only. The application itself is started with `pnpm dev` (development) or `pnpm build` + `pnpm start` (production).

For the full Chinese walkthrough — environment variables, creating the first administrator, ops commands, and known pitfalls — see [`DEPLOYMENT.md`](https://github.com/mnzn12138/reactive-resume/blob/main/DEPLOYMENT.md).

## Minimum requirements

<CardGroup cols={1}>
  <Card title="Node.js">Version 24 or newer. The pnpm version is pinned in the `packageManager` field of `package.json`.</Card>
  <Card title="Docker + Docker Compose">Only for PostgreSQL, Redis, and SeaweedFS.</Card>
  <Card title="Compute">1 vCPU / 1 GB RAM minimum, 2 GB recommended.</Card>
</CardGroup>

## Quickstart

Install dependencies and start the infrastructure:

```bash
pnpm install
docker compose -f compose.dev.yml up -d postgres redis seaweedfs seaweedfs_create_bucket
```

Wait for the services to report healthy:

```bash
docker compose -f compose.dev.yml ps
```

Create your env file:

```bash
cp .env.example .env
```

The hostnames in `.env.example` are Docker service names, which only resolve inside the container network. When the app runs on the host, change them to `localhost` and generate a fresh `AUTH_SECRET`:

```bash
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/postgres"
S3_ENDPOINT="http://localhost:8333"
REDIS_URL="redis://localhost:6379"
AUTH_SECRET="<openssl rand -hex 32>"
```

Start the app:

```bash
pnpm dev
```

Open <http://localhost:3000>. In dev mode Vite serves port 3000 and proxies API requests to the server on port 3001, so you only ever need port 3000.

## Running in production

```bash
pnpm build
pnpm start
```

## Environment variables

The authoritative reference is [`.env.example`](https://github.com/mnzn12138/reactive-resume/blob/main/.env.example) — every variable is listed there with a comment explaining it.

The ones you must set for a working deployment are `APP_URL`, `DATABASE_URL`, and `AUTH_SECRET`. `REDIS_URL` is required for the AI agent workspace, and the `S3_*` variables are optional.

<Warning>
  The app reads its configuration from the `.env` file at the repository root, and it does so once at module load. After editing `.env`, restart the server — watch mode will not pick up the change.
</Warning>

## Creating the first administrator

Accounts created through the sign-up form are regular users, and `/admin` redirects them away. Promote the first administrator from the CLI:

```bash
pnpm admin:promote -- you@example.com
```

## Health checks

`GET /api/health` returns HTTP 200 with a JSON body describing the `database` and `storage` checks. It returns HTTP 503 when either check fails, which makes it safe to wire into a reverse proxy or uptime monitor.

```bash
curl -i http://localhost:3000/api/health
```

## Backups

Dump the database and, if you rely on SeaweedFS for uploads, copy its data volume as well:

```bash
docker compose -f compose.dev.yml exec postgres pg_dump -U postgres postgres > backup.sql
```

## Updating

```bash
git pull
pnpm install
pnpm build
pnpm start
```

Migrations run automatically when the server starts, so they are normally nothing to do. To apply them without starting the app — first-time setup, or debugging a migration — run `pnpm db:migrate`.
